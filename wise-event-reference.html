OpenID Shared Signals · WISE Profile 1.0 draft 02

WISE Event Reference

Every event in the Workload Identity Security Events (WISE) profile: what triggers it, who sends it, what's in the payload, and how much weight it carries for a Receiver. WISE events are about a workload identity or the trust domain that issues it. They are sent by the trust domain authority, the party that issued the credentials, so several of them oblige the Receiver to act.

WISE draft 02 (19 July 2026) is by J. Lombardo (AWS), D. Sneeggen (Signicat), S. O'Dell (CVS Health) and P. Kasselman (Defakto Security). The authoritative text lives in identitymonk/openid-wise. This page was compiled alongside the IITP Event Reference for comparison.

Shared by every event

Each WISE event is a Security Event Token (SET, RFC 8417). Event types live under https://schemas.openid.net/secevent/wise/event-type/. Unlike IITP, the subject goes inside the event object as subject, and there are no common severity or confidence claims. Any event MAY carry CAEP's common optional claims:

ClaimReqMeaning
reason_adminOptionalA localized admin/audit message: a JSON object keyed by BCP 47 language tag. MUST be the object form, not a plain string.
reason_userOptionalA localized user-facing message, with the same structure.
initiating_entityOptionalWhat triggered the event, as defined in CAEP.admin user policy system
event_timestampOptionalDefined per event, usually as the time the change happened (NumericDate).

Subjects

Subject identifiers follow RFC 9493 using the uri format. A workload is named by its WIMSE identifier, such as wimse://trust.example.com/workload/payment-service, a spiffe:// ID, or an OAuth Client ID Metadata Document URI. Trust-domain-wide events name the trust domain itself, such as wimse://trust.example.com.

Credential types

Credential events take a credential_type: wit, wic, x509_svid, x509_generic, oauth_private_key_jwt, oauth_mtls, oauth_client_secret or api_key. Proof-of-possession types are preferred. The legacy types are included so that mixed estates can still signal. Bound-key compromise is expressed by revoking the credential with reason: key_compromise.
