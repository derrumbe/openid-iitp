IITP Event Reference

Every event in the Internet Infrastructure Threat Profile catalog: what triggers it, who sends it, what's in the payload, and what a Receiver can do about it. IITP events describe the state of an environment, such as a tenant, cloud account, cluster or workload, rather than a single user or session. They are detections, not commands: the Receiver decides whether and how to respond.

Shared by every event

Each IITP event is a Security Event Token (SET, RFC 8417). The event types live under https://schemas.openid.net/secevent/iitp/event-type/, and every one of them can carry these common claims in addition to its own.

ClaimReqMeaning
severityRecommendedThe Transmitter's view of how severe the condition is.low medium high critical
confidenceOptionalHow sure the Transmitter is that this isn't a false positive. Receivers SHOULD scale automated, high-impact responses by it.low medium high
recommended_actionsOptionalActions the Transmitter suggests, as advice only. A Receiver MUST NOT treat these as commands.
initiating_entityOptionalWhat produced the detection.detector policy admin system
event_timestampOptionalWhen the condition was detected. This can be later than when it began.
reason_admin / reason_userOptionalLocalized messages keyed by BCP 47 language tag, aligned with CAEP. reason_user is usually omitted.

Subjects

Draft 01 adds an environment subject format with environment_type (e.g. cloud-account, tenant, k8s-cluster), id, and optional provider and domain. The SSF complex format can pair an environment with a specific workload or resource inside it.

Clearing the condition

Transmitters SHOULD send a follow-up event when the condition ends, so Receivers can lift whatever restrictions they applied.

drift_status: reverted attack_status: resolved trust_status: restored
